## 사용 가이드

처음 사용하시는 분들을 위한 안내입니다.
아래 내용을 확인하고 프롬프트를 활용해 보세요.

01

### 프롬프트란?

AI(ChatGPT, Claude 등)에게 작업을 요청하는 텍스트입니다. 잘 작성된 프롬프트는 더 정확한 결과를 만들어냅니다.

02

### 복사하기

각 프롬프트의 [COPY] 버튼을 클릭하면 내용이 복사됩니다. 복사된 내용을 ChatGPT나 Claude에 붙여넣기(Ctrl+V) 하세요.

03

### 수정하기

프롬프트 내 {변수}는 실제 내용으로 바꿔주세요. 예: {회사명} → 우리회사

04

### 활용 팁

각 프롬프트는 중소기업 HR 업무에 최적화되어 있습니다. 회사 상황에 맞게 변형하여 활용하세요.

## // COMMON\_CONSTRAINTS

모든 프롬프트를 사용할 때 이 공통 규칙을 먼저 붙여넣으세요.

common-constraints.txt
COPY

```
공통 규칙(Common Constraints):
- 개인정보(PII)/민감정보를 요청하거나 생성하지 말 것
- 사실 근거 없는 단정 금지, 불확실하면 "가정/추정"으로 표시
- 차별/편향 유발 표현 금지(Bias Control)
- 객관적이고 공정한 톤 유지
- 노동법/판례 관련 내용은 "[법무 검토 필요]" 표기
- 출력은 지정된 포맷만 사용(불필요한 장문 금지)
- 마지막에 "내가 추가로 제공하면 좋은 정보" 5개를 질문으로 제시
```

// FRAMEWORK

## PROMPT CANVAS

좋은 프롬프트를 작성하기 위한 6가지 핵심 요소입니다.

#### ROLE (역할)

AI에게 부여할 전문가 역할  
예: "너는 노사관계 컨설턴트다"

#### TASK (목표)

수행할 업무 목표  
예: "일터혁신 진단 보고서를 작성하라"

#### CONTEXT (맥락)

상황/배경/정책  
예: "제조업 300인, 노조 있음"

#### INPUTS (입력)

제공할 데이터/정보  
예: 진단 결과 요약 (익명화)

#### CONSTRAINTS (제약)

제약조건  
예: "노사 중립, PII 금지"

#### OUTPUT FORMAT

원하는 출력 형태  
예: 보고서 양식, 표

01

## 기초 프롬프트

업무 시작을 위한 기본 프롬프트 패턴

### 1-1. Ask-Me-Questions Pattern (정보수집)

업무 시작 전 AI가 필요한 정보를 질문하게 만드는 패턴입니다. 불명확한 상태에서 바로 결과물을 생성하지 않고, AI가 먼저 질문으로 필요 정보를 수집합니다.

ask-me-questions.txt
COPY

```
역할(Role): 너는 HR 업무 전문가다.
목표(Task): 내가 하려는 산출물을 만들기 전에, 필요한 정보가 무엇인지 질문을 통해 수집하라.
규칙(Constraints):
- 추측하지 말고(Do not assume), 불명확한 부분은 질문으로 확인하라.
- 개인정보(PII) 및 민감정보를 요청하지 말아라.
- 한 번에 최대 5개 질문, 우선순위 높은 것부터.
- 충분한 정보가 확보되면 "정보 수집 완료. 작성 시작합니다." 선언 후 작업.
출력 형식:
[질문 1]: (질문)
[질문 2]: (질문)
...

시작: "[산출물 유형]을 만들고 싶어"
```

### 1-2. Output Format Spec (출력 형식 지정)

원하는 출력 형식(표, 목록 등)을 정확히 지정하여 일관된 결과를 얻는 프롬프트입니다.

output-format.txt
COPY

```
역할(Role): 너는 문서 포맷팅 전문가다.
목표(Task): 아래 내용을 지정된 형식으로 변환하라.
출력 형식:
| 항목 | 내용 |
|------|------|
| [항목1] | (내용) |
| [항목2] | (내용) |
...

입력: [변환할 내용]
```

## 채용·전직지원 프롬프트

채용 공고 작성부터 전직지원 경력 코칭까지

### 2-1. JD 고도화 프롬프트

거친 JD 메모를 전문적인 채용 공고로 변환합니다. 차별적 표현 없이 매력적인 채용 공고를 작성해 줍니다.

jd-enhancement.txt
COPY

```
역할(Role): 너는 10년 차 채용 브랜딩 담당자다.
목표(Task): 아래 [JD 메모]를 바탕으로 {COMPANY_NAME}의 채용 공고 초안을 작성하라.
맥락(Context):
- 회사: {COMPANY_NAME}, {COMPANY_SIZE}, {INDUSTRY}
- 문화: {CORE_VALUES}
- 근무: {WORK_STYLE}
규칙(Constraints):
- 차별/편향 유발 표현 금지 (연령/성별/학력/출신 암시 금지)
- 성격 단정 표현("센스", "빠릿빠릿", "밝은 성격") → 행동 기반 표현으로 대체
- Must-have는 5개 이하, Nice-to-have 분리
- 문체: 해요체
출력 형식:
1. 우리가 해결하려는 문제 (2-3문장)
2. 이런 일을 합니다 (5-7개 bullet)
3. 이런 분을 찾습니다 (Must-have 5개 이하)
4. 이런 분이면 더 좋아요 (Nice-to-have 3개)
5. 합류하시면 (복리후생/성장기회 3-4개)
6. 채용 프로세스 (단계별)

입력:
---
[JD 메모 붙여넣기]
---
```

### 2-2. 이력서 스크리닝 Rubric

지원자 적합도를 일관된 기준으로 평가합니다. 객관적 사실 기반으로 서류전형 의견을 작성해 줍니다.

resume-screening.txt
COPY

```
역할(Role): 너는 {ROLE} 직무 채용을 담당하는 리크루터다.
목표(Task): 아래 이력서 요약을 분석하여 서류전형 의견을 작성하라.
맥락(Context):
- 회사: {COMPANY_NAME}
- 직무: {ROLE}
- 레벨: {LEVEL}
- 필수 역량: {MUST_HAVE}
규칙(Constraints):
- 입력 근거 없는 추측 금지 (예: "성실해 보임")
- 객관적 사실(경력 연차, 기술, 성과 수치)만 언급
- 확인 불가 시 "확인 필요" 표기
- PII(이름, 연락처) 언급 금지
출력 형식:
| 평가 영역 | 점수(1-5) | 근거 |
|----------|----------|------|
| 직무 관련 경력 | | |
| 필수 기술 스택 | | |
| 성과/임팩트 | | |
| 문화 적합성 | | |
| 성장 가능성 | | |
| **종합** | /25 | |

추천: Pass / Interview / Hold (이유 1-2줄)
면접 시 확인 필요 사항: (3개)

입력:
---
[이력서 요약 붙여넣기 - 이름/연락처 마스킹]
---
```

### 2-3. Structured Interview Kit

STAR 기반 구조화 면접 질문지를 생성합니다. 역량별 질문, Follow-up, 평가 기준까지 포함합니다.

interview-kit.txt
COPY

```
역할(Role): 너는 구조화 면접을 설계하는 HR 전문가다.
목표(Task): {ROLE} 직무 면접 질문지(STAR 기반)를 생성하라.
맥락(Context):
- 직무: {ROLE}
- 핵심 역량: {COMPETENCIES}
- 면접 시간: {DURATION}분
규칙(Constraints):
- STAR(Situation-Task-Action-Result) 형식 기반
- 각 역량당 Main Q + Follow-up 2개
- 차별적 질문 금지 (가족, 결혼, 출신 등)
출력 형식:
| 역량 | Main Q | Follow-up 1 | Follow-up 2 | 평가 포인트 |
|------|--------|-------------|-------------|------------|
| {역량1} | | | | |
| {역량2} | | | | |
...

입력:
---
[직무/역량 정보]
---
```

### 2-4. 경력전환 코칭 프롬프트

경력 전환을 원하는 직원을 위한 코칭 프롬프트입니다. 재취업 전략, 이력서 피드백, 면접 준비를 지원합니다.

career-coaching.txt
COPY

```
역할(Role): 너는 경력 개발 전문 코치다.
목표(Task): 아래 [경력 요약]을 바탕으로 맞춤형 경력전환 전략을 수립하라.
맥락(Context):
- 이직 사유: {REASON} (이직희망/구조조정/퇴직/경력전환)
- 경력: {YEARS}년
- 희망 분야: {TARGET_FIELD}
- 지역: {LOCATION}
규칙(Constraints):
- 개인 판단/평가 금지, 객관적 코칭 관점 유지
- 재취업 가능성에 대한 단정적 표현 금지
- 현실적이면서 긍정적인 톤 유지
출력 형식:
1. 경력 자산 분석 (강점 5개)
2. 전환 가능 직무/산업 (3개)
3. 추천 활동 (3개월 로드맵)
4. 활용 가능한 지원 프로그램 (정부/민간)
5. 주의 사항 및 권고

입력:
---
[경력 요약 붙여넣기 - 이름/연락처 마스킹]
---
```

```
- **긍정적이되 현실적인 톤** - 막연한 희망 금지
```

## 온보딩/교육/컨설팅 프롬프트

신입사원 온보딩, 일터혁신 컨설팅, 유연근무제, 교육과정 설계

### 3-1. 온보딩 30일 계획 생성기

신입사원의 30-60-90일 온보딩 계획을 생성합니다. 직무별 맞춤 적응 프로그램을 설계합니다.

onboarding-plan.txt
COPY

```
역할(Role): 너는 온보딩 설계 전문가다.
목표(Task): 아래 [신입사원 정보]를 바탕으로 30-60-90일 온보딩 계획을 수립하라.
맥락(Context):
- 입사자: {NAME} (익명 처리 가능)
- 직무: {ROLE}
- 경력: {EXPERIENCE}
- 부서: {DEPARTMENT}
규칙(Constraints):
- 직무 특성 반영
- 단계별 학습 목표 명확히
- 멘토/버디 역할 포함
- 체크포인트 및 피드백 주기 명시
출력 형식:

## 온보딩 계획: {ROLE}

### Phase 1: 적응기 (1-30일)
| 주차 | 목표 | 활동 | 담당 | 완료 체크 |
|------|------|------|------|----------|
| 1주 | | | | |
| 2주 | | | | |
```
